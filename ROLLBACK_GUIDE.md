# Mushavo Budget Web Push Rollback

This package restores Mushavo Budget to its last state before server-triggered Web Push was added.

It **keeps**:

- the installable PWA and offline cache;
- the notification bell and in-app notification centre;
- invitation notifications;
- payment reminders calculated while the app is open;
- the optional user-triggered browser notification permission;
- receipts/payment-proof uploads;
- multi-family management;
- the compact dashboard, month groups, and advanced member workload;
- authentication, reports, CSV export, and unrelated Supabase data.

It **removes**:

- VAPID Web Push subscriptions;
- closed-app server-triggered Push delivery;
- Push test delivery;
- device subscription controls and Push diagnostics;
- server reminder timezone/time preferences;
- the one-minute Supabase Cron job;
- the `send-reminders` Edge Function;
- the four Edge Function secrets;
- the Push outbox, delivery-attempt, subscription, and dispatch-log tables;
- the three Web Push SQL functions and related columns/index;
- in-app notification rows that were generated by the Web Push outbox.

## Important warning

The supplied cleanup SQL permanently deletes Web Push subscription and delivery data. It does not delete families, users, payments, receipts, invitations, or ordinary in-app notification records.

If you want a final backup, export these four tables from Supabase Table Editor before continuing:

- `push_subscriptions`
- `notification_outbox`
- `push_delivery_attempts`
- `notification_dispatch_runs`

Do not export or share the `endpoint`, `p256dh`, or `auth` subscription values unless the backup is stored securely.

## Step 1 — Run the permanent database cleanup

1. Sign in to Supabase.
2. Open the Mushavo Budget project.
3. Confirm the project reference is `kttkospkblwvguuwnhjj`.
4. Open **SQL Editor**.
5. Select **New query**.
6. Open this package's file:

   `supabase/migrations/20260828210000_remove_web_push_notifications.sql`

7. Copy the complete contents into SQL Editor.
8. Make sure the entire query is selected, then click **Run** once.

The final result contains these columns:

- `remaining_push_tables`
- `remaining_push_functions`
- `remaining_push_columns`

All three must show `0`.

The migration also unschedules `mushavo-push-reminders-every-minute` and deletes the two Vault entries created for it. It deliberately leaves `pg_cron`, `pg_net`, and Vault installed because other features may need those extensions later.

## Step 2 — Delete the deployed Edge Function

Open PowerShell in the project folder. Use `npx.cmd` because your PowerShell execution policy blocks the `.ps1` npm wrappers.

```powershell
npx.cmd supabase login
```

```powershell
npx.cmd supabase link --project-ref kttkospkblwvguuwnhjj
```

Check that the function currently exists:

```powershell
npx.cmd supabase functions list --project-ref kttkospkblwvguuwnhjj
```

Delete only the Web Push function:

```powershell
npx.cmd supabase functions delete send-reminders --project-ref kttkospkblwvguuwnhjj
```

Run the list command again and confirm `send-reminders` is gone.

## Step 3 — Delete the Edge Function secrets

Remove only the four secrets created for Web Push:

```powershell
npx.cmd supabase secrets unset VAPID_PUBLIC_KEY VAPID_PRIVATE_KEY VAPID_SUBJECT CRON_SECRET --project-ref kttkospkblwvguuwnhjj
```

Confirm their names are gone:

```powershell
npx.cmd supabase secrets list --project-ref kttkospkblwvguuwnhjj
```

Do not delete Supabase's built-in `SUPABASE_URL`, anonymous/publishable key, or service-role configuration.

## Step 5 — Clean `config.js` without losing the real Supabase key

`config.js` is intentionally not included because your deployed file contains your current working Supabase publishable key. Do not replace it with a placeholder.

Open your existing `config.js` and remove only the VAPID property and its explanatory comments. The final structure should be:

```js
window.MUSHAVO_BUDGET_CONFIG = {
  supabaseUrl: "https://kttkospkblwvguuwnhjj.supabase.co",
  supabasePublishableKey: "KEEP_YOUR_CURRENT_WORKING_PUBLISHABLE_KEY_HERE"
};
```

Keep the real value already present in `supabasePublishableKey`. Never put a Supabase secret/service-role key in this browser file.

## Step 6 — Remove Web Push source files

Because you deployed the Push migration manually through SQL Editor, remove these Web Push-only files from your local project after the rollback succeeds:

- `supabase/cron.sql`
- `supabase/migrations/20260828090000_web_push_notifications.sql`
- the complete `supabase/functions/send-reminders/` folder
- `supabase/functions/.env.example` if it contains only the VAPID/cron example values

Your `supabase/config.toml` from the Push package contains only a `[functions.send-reminders]` section. Delete that section. If the file has no other settings afterward, the file itself can be removed.

If the original Push migration is already tracked in a formal shared migration history, keep it and add the new inverse migration after it instead of rewriting published history.

## Step 7 — Activate the no-Web-Push service worker

The supplied worker uses this cache name:

```text
mushavo-budget-v17-no-web-push
```

It contains no `push` or `notificationclick` event handlers. On activation it removes the existing device's Web Push subscription, deletes older PWA caches, and keeps ordinary offline caching.

After publishing the replacement files:

1. Close every Mushavo Budget browser tab and installed PWA window.
2. Open the website in Chrome.
3. Press `Ctrl + F5` once. This is the final one-time refresh needed to replace the old Push worker.
4. Close that tab and open a normal new tab.
5. Open `https://YOUR-WEBSITE/sw.js`.
6. Confirm the first line contains `mushavo-budget-v17-no-web-push`.
7. Search that file for `self.addEventListener("push"`. It must not be present.

The new worker never caches `config.js`, so normal new tabs should continue using the current Supabase key without repeated `Ctrl + F5` refreshes.

## Step 8 — Final checks

Check the following after signing in:

1. The notification bell still opens.
2. Invitation and in-app payment reminders still appear.
3. The old server Push delivery settings are gone.
4. There is no **Send test notification** button.
5. The Settings page has the original **Enable browser reminders** control.
6. Families, members, payments, receipts, reports, and dashboard cards still load.
7. Opening a normal new tab does not show `Invalid API key`.
8. Supabase Edge Functions no longer lists `send-reminders`.
9. Supabase Secrets no longer lists the four Web Push secret names.
10. The SQL verification result reports zero remaining Web Push tables, functions, and columns.

When you later decide to use Capacitor, native scheduled/remote notifications should be planned separately. This rollback does not install Capacitor or remove the existing PWA.
